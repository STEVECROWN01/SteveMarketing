(1) FAILLE RÉELLE — L'ADMIN DE PRODUCTION ACCEPTAIT LES JETONS FORGÉS AVEC LE SECRET PUBLIC DU DÉPÔT ; FAIL-CLOSED PARTOUT. Constat initial (lecture de src/lib/admin-auth.ts) : les deux primitives d'authentification portaient des valeurs de repli EN DUR dans un dépôt PUBLIC — verifyPassword() acceptait « stevens-admin-2026 » sans ADMIN_PASSWORD défini, et getSessionSecret() signait/validait les sessions avec « stevens-admin-session-secret-change-me » sans ADMIN_SESSION_SECRET. VÉRIFICATION EN PRODUCTION (curl sur stevensakpovi.vercel.app, 19/11) : le mot de passe par défaut est REFUSÉ (ADMIN_PASSWORD est bien défini — 401), MAIS un jeton de session forgé en local avec le secret public du dépôt a PASSÉ verifySessionToken() — la réponse de /api/admin/leads n'était pas le 401 « Non autorisé » attendu mais un 503 « base de données indisponible » : le code avait validé la session et atteint la requête Prisma. ADMIN_SESSION_SECRET n'est PAS défini sur Vercel ; seule l'absence de base connectée limite aujourd'hui l'impact — dès la mise en place de la base documentée (DEPLOIEMENT.md), l'admin aurait été accessible à quiconque lit le dépôt GitHub. CORRECTIF — FAIL-CLOSED EN PROFONDEUR (src/lib/admin-auth.ts) : verifyPassword() retourne false sans ADMIN_PASSWORD (aucune soumission acceptée) ; verifySessionToken() retourne false sans secret valide ≥ 16 caractères (aucun jeton validé, forgé ou non) ; createSessionToken() lève une erreur explicite plutôt que de signer avec un secret public ; nouveau isAuthConfigured() pour la route. LA ROUTE LOGIN REFUSE EN AMONT (src/app/api/admin/login/route.ts) : configuration incomplète → 503 « Espace administrateur non configuré — définissez les variables d'environnement listées dans DEPLOIEMENT.md » — message générique volontairement SANS préciser quelle variable manque (cette information appartient au propriétaire ; un attaquant distant n'apprend rien d'exploitable). VÉRIFIÉ EN LOCAL (build sans variables, curl) : mot de passe par défaut du dépôt → 503 non configuré (avant : il aurait OUVERT une session) ; n'importe quel mot de passe → 503 ; jeton forgé avec le secret public → 401 « Non autorisé » (avant en prod : accepté, prouvé) ; logout → 200 inoffensif. CONSÉQUENCE ASSUMÉE ET À CONNAÎTRE : tant que ADMIN_SESSION_SECRET n'est pas défini dans Vercel, l'admin de production répondra 503 — indisponible plutôt qu'ouvert, c'est le principe même du fail-closed ; définir la variable (openssl rand -hex 32) rétablit l'accès immédiatement, sans redéploiement (variable lue au runtime par la route nodejs).
