AUDIT SERVEUR — EN-TÊTES DE SÉCURITÉ, SITEMAP ET PAGE 404 : LES TROIS DÉFAUTS DU CÔTÉ FILS TROUVÉS AU CURL, CORRIGÉS ET VÉRIFIÉS (demande de l'éditeur, 19/11 : « poursuit l'audit » puis « continue ») — cinquième volet après l'audit structurel/SEO (4e51251), l'application de ses recommandations (f690a43), l'audit accessibilité/performance/formulaires (2cbe3c3) et le creusement CLS/faux négatif aria (baa813e) : les volets précédents observaient le site DANS LE NAVIGATEUR ; celui-ci sonde ce que le SERVEUR envoie — en-têtes HTTP, robots.txt, sitemap.xml, comportement des URLs inconnues — sur le build standalone local ET sur la production Vercel. (1) AUCUN EN-TÊTE DE SÉCURITÉ — CINQ EN-TÊTES AJOUTÉS (next.config.ts). Constat au curl (local ET production) : la réponse de « / » ne portait NI X-Content-Type-Options, NI X-Frame-Options, NI Referrer-Policy, NI Permissions-Policy, NI Strict-Transport-Security. Correctif : headers() de next.config appliqués à « /:path* » (toutes les réponses ; alimente la configuration de routage Vercel comme le standalone) — nosniff (le navigateur ne devine plus le type MIME), X-Frame-Options SAMEORIGIN (anti-clickjacking : le site ne peut plus être intégré dans un iframe tiers — sans affecter les iframes que le site EMBARQUE, comme le widget Calendly), Referrer-Policy strict-origin-when-cross-origin (explicite, c'est la valeur par défaut des navigateurs modernes), Permissions-Policy camera/microphone/geolocation/payment/usb désactivés (le site n'en utilise aucun ; les scripts tiers ne peuvent plus les demander), Strict-Transport-Security max-age=31536000 SANS includeSubDomains (volontairement conservateur — aucun sous-domaine connu ; ignoré sans effet sur le HTTP de prévisualisation locale). PAS de CSP verrouillée, décision documentée dans le fichier : le site charge des scripts inline légitimes (détection hover, JSON-LD) et des scripts tiers (Calendly, Google Fonts) — une CSP stricte exigerait une infrastructure de nonces hors du périmètre de ce volet. Vérifié au curl après rebuild : les 5 en-têtes présents sur « / » ET propagés sur « /robots.txt ».

(2) SITEMAP : 11 URLs À FRAGMENT QUI SONT UNE SEULE URL — RÉDUIT À L'ENTRÉE HONNÊTE (src/app/sitemap.ts). Constat : le sitemap listait « /#/methode », « /#/referencement-seo », « /#/publicite-meta-ads », « /#/realisations », « /#/a-propos », « /#/contact », « /#/demander-un-devis », « /#/audit-gratuit », « /#/reserver-un-appel », « /#/mentions-legales » en plus de la racine. Or les crawleurs IGNONENT les fragments : chaque « /#/page » est lu comme « / » — 10 entrées qui se résolvent toutes vers la même page racine, du bruit de duplication dans Search Console et un sitemap qui promet 11 URLs indexables alors que le site (routage par fragment, une seule route serveur) N'EN A QU'UNE. Correctif : le sitemap ne contient plus que l'URL racine (lastModified au build, changeFrequency monthly, priority 1) — le sitemap honnête d'un site à une URL indexable ; les pages virtuelles restent atteignables par la navigation interne et les moteurs exécutant le JavaScript voient leur contenu sur l'URL racine, mais aucune n'est une URL indexable distincte. Vérifié au curl : une seule balise <loc> dans sitemap.xml. (robots.txt inchangé et correct : Allow /, Disallow /api/, lien vers le sitemap avec l'URL canonique vérifiée sur la production.)

(3) PAGE 404 ANGLAISE — PAGE 404 FRANÇAISE CRÉÉE (src/app/not-found.tsx, nouveau fichier). Constat : toute URL inconnue (« /nimporte-quoi », faute de frappe dans un lien partagé) recevait la page 404 PAR DÉFAUT de Next.js — « 404: This page could not be found. », en ANGLAIS, sans style ni issue de sortie — sur un site 100 % français. Correctif : composant serveur minimal dans la langue visuelle du site (fond #1c1c1c plein écran, eyebrow « ERREUR 404 », H1 « Cette page n'existe pas — ou a changé d'adresse. » en Sora via font-display, texte d'explication, CTA plein blanc « Retour À L'Accueil » vers « / » — la racine affiche l'accueil, point d'entrée de toute la navigation à fragments) ; PAS de routeur applicatif (le contexte du routeur à fragments n'existe pas sur une page serveur — simple lien) ; titre d'onglet « Page introuvable — Stevens Akpovi » ; Next.js marque automatiquement la page noindex (correct : une 404 ne doit pas être indexée — constaté dans le HTML servi). Vérifié par sonde dédiée (scripts/verify-404-2026-11-19.js, 22 contrôles sur desktop 1440 + iPhone 13) : statut 404 conservé (le statut HTTP correct est la moitié du travail SEO d'une 404), texte anglais ABSENT, eyebrow/H1/CTA exacts, police Sora mesurée sur le H1, CTA fond blanc, centrage horizontal ET vertical vérifiés géométriquement, zéro débordement, zéro erreur console (après correction de la sonde : le journal Chrome « Failed to load resource: status of 404 » est le DOCUMENT lui-même qui répond 404 — voulu, exclu ; toute autre erreur reste comptée) ; confirmation pixel des captures (fond sombre aux 4 coins, texte clair + bouton blanc dans la bande centrale sur les deux appareils).
